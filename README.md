# RP_self_repair

This repository contains the source code used to test different **oversampling techniques** and analyze how they affect the performance of a **regressor optimized via genetic algorithm optimization**.

---

## 📁 Folder Structure

The repository is organized as follows:

- **`configuration_optimizer/`** — contains the optimization algorithm used for testing.  
- **`data/`** — includes the dataset for the initial regressor training and configuration files used by the tester to parse data.  
- **`model_checker/`** — contains the **UPPAL** model checker used by the tester.  
- **`notebook/`** — holds the output data referenced in the paper and visualized in the notebook.  
- **`output/`** — stores the final results generated by the tester.  
- **`self_repair/`** — includes all scripts and classes necessary for the tester’s functionality.  
- **`utils/`** — provides utility scripts such as data parsing and logging helpers.  

---

## Overview

To run an experiment using the tester, it is **recommended** to work only with the file **`Testing_mono.py`**.  
This script is designed to execute controlled experiments involving oversampling using the function  
`run_oversampling_pipeline` from the `self_repair` module.  

It automates the process of testing multiple parameter configurations and saves the resulting statistics for later analysis.

---

## Usage

Run the script from the command line, providing a single argument: the **test name**.

```bash
python run_experiment.py <test_name>
````
---

## 📊 Outputs

All results are saved under:

```
output/data_<test_name>/
```

The following files will be generated:

* **`oversampling_results_invalid_configs.pkl`** — raw statistics from each experiment run.
* **`boxplot_data_invalid_configs.csv`** — processed results ready for visualization (e.g., boxplots).

---

## ⚙️ Configurable Parameters

### **`regressor_points`**

* **Type:** `List[int]`
* **Description:** Number of data points used by the regressor model.
* **Effect:** Larger values may improve regression accuracy but increase computation time.
* **Default:** `[100]`
* **Example:** `[50, 100, 200]`

---

### **`resampling_points`**

* **Type:** `List[int]`
* **Description:** Number of synthetic samples generated during oversampling.
* **Effect:** More samples can improve class balance but may increase overfitting risk.
* **Default:** `[10]`
* **Example:** `[10, 20, 50]`

---

## ⚙️ `run_oversampling_pipeline` Internal Parameters

These parameters are fixed within the script but can be modified directly in the source code if needed.

| Parameter          | Default                  | Description                                            |
| ------------------ | ------------------------ | ------------------------------------------------------ |
| `n_data_to_verify` | `100`                    | Number of data points used for verification per run.   |
| `max_iterations`   | `30`                     | Maximum number of iterations in the oversampling loop. |
| `n_samples`        | from `resampling_points` | Number of generated samples.                           |
| `points_regressor` | from `regressor_points`  | Number of regressor training points.                   |
